## 한 줄 정의

하이브리드(WebView) 앱의 하단 탭 목록 · 선택 · 보임 여부를 웹 코드 한 곳이 정해 브리지 메시지로 보내고, 네이티브 앱은 탭 정보를 갖지 않고 받은 대로 네이티브 탭바를 그리는 구조.

## 핵심

**왜**: 탭을 네이티브 코드에 적으면 이름 · 순서 · 개수를 바꿀 때마다 스토어 심사가 필요하고, 웹 탭바와 값이 어긋난다. 정본을 웹에 두면 웹 배포만으로 바뀌고, 브라우저용 웹 탭바와 앱 탭바가 같은 배열에서 나온다.

**메시지 구성 (웹 → 앱)**
- `setTabs { tabs: [{ id, to, label, icon }] }` — 탭 화면 레이아웃이 마운트될 때 보낸다. 벗어나면 빈 배열(= 탭바 없음).
- `state { path, activeTab, tabBarVisible, overlayOpen, canGoBack }` — 경로 · 탭 목록 · 열린 오버레이가 바뀔 때마다. 한 틱에 한 번으로 묶어 보낸다.
- 앱 → 웹: `tabSelected { to }`(네이티브 탭을 눌렀을 때), `tabBarChanged { visible, height }`(웹이 그 높이만큼 본문 아래를 비운다).

**보임 규칙 (네이티브)**
- `reserved = 탭 목록 있음 && tabBarVisible` — 탭 화면이라 탭바 자리가 있다.
- `shown = reserved && !overlayOpen` — 바텀시트 · 모달이 열리면 탭바만 숨긴다. 자리는 유지해야 딤 뒤 본문이 튀지 않는다.

**오버레이 추적 (웹)**: 시트 · 다이얼로그 · 팝오버가 열릴 때 공용 스택에 등록하고 닫힐 때 내린다(`useBackClose(open, onClose)` 같은 훅 하나). 스택이 비었는지가 `overlayOpen`. 같은 스택이 Android 하드웨어 뒤로가기에서 "가장 위 오버레이부터 닫기"에도 쓰인다. 훅을 빠뜨린 커스텀 모달은 앱이 모르므로 탭바가 그 위에 남는다.

**앱 배포가 필요한 경계**
- 아이콘은 `iconKey` → 네이티브 심볼(예: SF Symbol) 매핑이라, 새 키는 **앱 먼저 배포 → 웹이 사용** 순서. 모르는 키는 기본 아이콘으로 그려 깨지지 않게 한다.
- 새 브리지 기능은 앱이 지원 메서드 목록을 알려 주고(`getVersion.methods`), 웹은 없으면 웹 폴백을 쓴다 → 웹을 먼저 배포해도 옛 앱이 깨지지 않는다.

## 예시

| 방식 | 탭 정본 | 바꿀 때 심사 |
|---|---|---|
| 웹이 앱에 알림 (이 패턴) | 웹 코드 | 불필요 |
| 원격 설정 · 서버 JSON | 서버 | 불필요 |
| 네이티브 하드코딩 | 앱 코드 | 매번 필요 |
| 웹 탭바만 사용 | 웹 코드 | 불필요(대신 네이티브 질감은 덜함) |

## 더 알아볼 것

- 스토어 심사 기준: 웹을 감싸기만 한 앱의 최소 기능 요건, 심사 후 원격으로 동작을 바꾸는 것의 허용 범위 (App Store Review Guidelines 4.2 · 2.5.2 원문 확인)
- 브리지 계약을 한 JSON 에서 웹 · iOS · Android 코드로 생성하고 같은 테스트 사례를 공유하는 방법
- Server-Driven UI 와의 차이(탭만 원격인가, 화면 구조 전체가 원격인가)

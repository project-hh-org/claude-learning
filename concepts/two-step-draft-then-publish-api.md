## 한 줄 정의
글이나 미디어를 한 번에 게시하지 않고, 초안을 먼저 만든 뒤 초안 ID로 게시를 따로 호출하는 API 설계 패턴이다.

## 핵심
- 1단계는 초안(컨테이너)을 만든다. 이 단계에서 권한과 입력 형식이 검사된다.
- 2단계는 초안 ID를 넣어 게시한다. 초안 ID가 없거나 잘못되면 "없는 초안" 오류(400)가 나올 수 있다.
- 두 단계는 권한 문제가 다르게 나타날 수 있으므로 각 단계의 응답을 따로 확인해야 한다.
- 초안에는 유효 기간이 있을 수 있다. 만들어 둔 초안은 오래 두면 사라질 수 있으므로 게시 직전에 만드는 편이 안전하다.
- 이미지처럼 외부 자원이 필요한 경우, 서버가 공개 URL로 직접 가져가는 방식이면 그 URL에 접근 가능해야 한다.

## 예시
- Graph API 방식: 1단계 미디어 초안 생성(200, 초안 ID 반환) → 2단계 초안 ID로 게시 호출.
- 가짜 초안 ID를 넣었을 때 400이 나오면 2단계 입력 검증이 동작한 것이다.

## 한 줄 정의
대화 로그를 정규식과 길이 기준으로 골라내면, 형식 변화에 따라 실패해도 에러 없이 결과 0건으로 끝날 수 있다.

## 핵심
- 질문 패턴이 좁으면 실제 질문 대부분이 빠진다. `~이/가 뭐` 같은 형태만 잡으면 자연스러운 다른 질문들이 전부 제외된다.
- `^` 앵커는 메시지 앞에 시스템 래퍼(예: `<system-reminder>`)가 붙는 경우 항상 실패한다. 래퍼를 먼저 제거한 뒤 비교한다.
- 답변을 "질문 직후 블록 하나"로 잡으면 "확인해볼게요" 같은 짧은 중간 발화만 잡혀, 길이 기준에서 걸러진다. 다음 사용자 메시지 전까지의 assistant 텍스트 전체를 본다.
- thinking 블록이 빈 값으로 저장된 경우가 많으면 키워드 추출 자체가 불가능하다. 규칙을 짜기 전에 입력 재료가 실제로 어떤지 먼저 센다.
- 종료 코드 0과 후보 0건은 정상처럼 보여 실패를 숨긴다. 입력 대비 매치 수를 로그에 남겨야 0건의 원인을 알 수 있다.

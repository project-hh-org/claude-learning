## 핵심 아이디어

레거시 어드민 화면을 자동화할 때 자주 막히는 지점은 두 가지다. 네이티브 `alert`·`confirm` 창이 실행을 멈추는 것, 그리고 스크립트로 보낸 이벤트로는 입력이 확정되지 않는 것이다. 앞의 것은 함수를 덮어써서 해결하고, 뒤의 것은 실제 클릭으로 확정한다.

## 1. alert·confirm 가로채기

네이티브 대화상자는 자동화 도구의 다음 동작을 막는다. 저장 버튼을 누르기 전에 페이지 안에서 두 함수를 교체한다.

```js
window.__msgs = [];
window.alert = (msg) => { window.__msgs.push(msg); };
window.confirm = (msg) => { window.__msgs.push(msg); return true; };
document.querySelector('#submitBtn').click();
// 이후 window.__msgs를 읽어 "저장되었습니다" 같은 결과 문구로 성공 여부를 판정
```

- `confirm`은 `true`를 돌려줘야 '확인'을 누른 것과 같다.
- 메시지를 버리지 말고 배열에 모아 두면, 저장 성공 문구를 검증 신호로 쓸 수 있다.

## 2. 합성 이벤트로 확정되지 않는 입력

트리 위젯에서 새 항목의 이름을 바꿀 때, 입력창 값을 스크립트로 넣고 jQuery로 `blur`를 발생시켜도 이름이 확정되지 않았다. 순서를 이렇게 바꾸자 안정적으로 확정됐다.

1. '추가' 버튼을 클릭한다.
2. 새로 생긴 입력창의 `value`를 스크립트로 직접 넣는다.
3. 페이지의 다른 곳을 **실제 마우스로 클릭**해 입력을 확정한다.
4. 표시 여부 같은 나머지 필드를 설정하고 저장한다.

위젯이 프로그램으로 만든 이벤트와 사용자 입력을 다르게 처리할 수 있다. 값 입력은 스크립트로, 확정은 실제 입력으로 나누면 두 방식의 장점을 같이 쓸 수 있다.

## 언제 쓰나

- API가 없어서 관리자 화면을 직접 조작해야 하는 반복 작업 (테스트 데이터 시딩, 일괄 설정)
- headless 브라우저나 에이전트가 네이티브 대화상자에서 멈추는 경우

## 주의

- 함수 덮어쓰기는 그 페이지에만 적용된다. 페이지를 이동하면 다시 넣어야 한다.
- `confirm`을 무조건 `true`로 만들면 삭제 확인도 자동으로 통과한다. 삭제가 섞인 흐름에서는 메시지를 보고 분기한다.
- 저장 직후 다시 조회하면 옛 값이 보일 수 있다. 반영 지연이 있는 시스템이라면 성공 문구나 일정 시간 뒤 재조회로 검증한다.

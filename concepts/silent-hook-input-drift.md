## 핵심 아이디어

자동화가 에러 없이 끝나는데 결과가 0건이면, 코드보다 **입력 데이터가 아직 예전과 같은지**부터 확인한다. 성공 여부만 보는 모니터링으로는 이런 실패가 보이지 않는다.

## 실제로 있었던 일

Claude Code 세션 기록(JSONL)을 읽어 아이디어 후보를 뽑는 Stop hook이 있었다. 응답의 사고 과정(thinking) 텍스트에서 "이런 방법도", "만들어보면 좋겠다" 같은 문구를 정규식으로 찾는 방식이다.

- hook은 매 턴 100ms 안팎에 에러 없이 끝났다.
- 그런데 8월 7일 이후로 결과 파일이 하나도 생기지 않았다.

세션 기록을 월별로 다시 세어 보니 입력이 달라져 있었다.

| 월 | 내용이 남은 thinking 블록 | 평균 길이 |
|---|---|---|
| 7월 | 708 / 708 | 810자 |
| 8월 | 2,088 / 4,574 | 619자 |
| 9월 | 1,434 / 5,781 | 156자 |
| 10월 | 640 / 2,186 | 157자 |

9월부터 대부분의 블록이 비어 있었고, 남은 것도 150자 안팎의 짧은 요약이었다. 정규식이 걸릴 문장 자체가 사라진 것이다. 8~10월 전체를 같은 패턴으로 다시 돌려도 일치는 8월 세션 3건뿐이었다.

## 같이 드러난 문제

같은 방식의 다른 hook(정의 질문을 뽑는 쪽)은 계속 동작했지만 다른 문제가 있었다.

- Stop hook은 세션 끝이 아니라 **매 턴** 실행된다. 매번 전체 기록을 다시 훑어서 같은 후보를 새 파일로 또 만들었다. 파일 118개 중 실제 주제는 10개였다.
- 파일명이 초 단위 시각이라, 같은 초에 생긴 후보끼리 덮어썼다.

## 교훈

- 다른 시스템이 만든 데이터에 기대는 자동화는, 그 데이터의 형식이 바뀌면 에러 없이 멈춘다. '실행됐다'와 '결과를 냈다'를 따로 확인해야 한다.
- 결과 건수가 갑자기 0이 되면 알리는 것만으로도 몇 달짜리 공백을 막을 수 있다.
- 세션당 한 번 돌아야 하는 작업은 Stop이 아니라 SessionEnd에 건다.

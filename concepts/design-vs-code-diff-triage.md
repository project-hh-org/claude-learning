## 한 줄 정의
디자인 시안과 기준 브랜치 코드의 차이를 원인에 따라 나눠 정리하는 방법이다.

## 핵심
- 차이를 한 덩어리로 보지 않고 원인별로 나눈다.
  1. 작업은 있으나 기준 브랜치에 아직 올라가지 않은 것(미병합 브랜치에만 구현)
  2. 시안 이후에 새로 생긴 화면이라 아무 브랜치에도 없는 것
  3. 팀원의 다른 커밋 때문에 생긴 것
  4. 규칙이나 결정으로 일부러 시안과 다르게 둔 것
  5. 시안이 아니라 댓글로만 남은 요청
- 비교 기준(기준 브랜치와 커밋)과 시안 버전을 함께 적어 두어야 나중에 같은 결론을 재현할 수 있다.
- 시안 자체의 숫자나 문구가 맞지 않으면 시안과 코드 중 어느 쪽이 틀렸는지 따로 표시한다.
- 분류가 끝나면 각 항목을 '개발 필요', '논의 필요', '해당 없음'으로 다시 나눈다. 지시가 분명한 것만 바로 개발 대상으로 넘긴다.

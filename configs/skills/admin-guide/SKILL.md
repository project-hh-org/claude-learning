# 어드민/웹 사용 가이드 일괄 생성 (admin-guide)

비개발 운영자용 **사용 가이드 사이트**를 코드 기반으로 일괄 생성하는 워크플로우다. 어떤 프로젝트에도 적용되도록, 경로/URL을 입력으로 받아 라우트를 자동 추출한다.

## 핵심 원칙
- **개발 코드 내용 비노출**: 변수명/함수명/파일경로/API URL/내부 구현/수식 금지. 화면에 보이는 한글 버튼·탭·컬럼·토스트만 인용.
- **추측 금지**: 코드에서 확인 안 된 동작은 적지 않는다.
- **캡쳐+하이라이트**: 색 구분 번호 배지(상단버튼=빨강·탭=보라·검색필터=초록·표헤더=파랑) + 같은 색 테두리.
- 직렬 캡쳐는 브라우저 1개라 오래 걸린다 → resumable 트래커를 항상 남긴다.

---

## 0) 입력 확정 (없으면 사용자에게 1회 질문)
필요한 값:
- **코드베이스 경로(주)**: 어드민 프로젝트 루트 (예: `../my-admin`)
- **라이브 URL**: 캡쳐 대상 (예: `https://admin.example.com`)
- **가이드 산출 위치**: 보통 별도 정적 사이트 레포 (md + public/captures). 없으면 사용자에게 확인.
- (선택) **교차 코드베이스**: 백엔드/프론트/앱 경로
- (선택) **범위**: 전체 / 특정 섹션 / 어려운 페이지 우선
- (선택) **깊이**: 페이지당 1폴더 깊게 / 하위 화면도 별도 문서
- (선택) **폴더 그룹화**: 페이지별 개별 상위 폴더 / 메뉴 섹션 그룹

> 이미 대화에서 정해졌으면 다시 묻지 않는다.

## 1) 라우트 워크리스트 추출 (스카우트, 인라인)
프로젝트 타입을 자동 감지해 "사용자가 실제 들어가는 화면" 목록을 만든다:
- **메뉴 정의 파일이 있으면 그것이 1순위** (예: 대시보드/사이드바의 `label→route` 배열). `grep` 으로 `adminDrawerList` 류, 사이드바 컴포넌트, nav 설정을 찾는다.
- 없으면 `pages/**` (Next Pages Router), `app/**/page.*` (App Router), 또는 React Router `<Route path>` 를 수집.
- 외부 링크(redash/대시보드 등 `https://`)는 가이드 대상에서 제외.
- 라벨 정리: `[NEW]`·`[C1 Score]` 같은 태그 prefix 제거, 폴더 슬러그는 공백→`_`, 슬래시 제거, 중복은 의미로 구분(예: 프로모션_기존/프로모션_신규).
- 결과를 `<guide-repo>/.worklist/worklist.json` 에 `{section,label,folder,route,order}` 배열로 저장.

## 2) 페이지별 가이드 작성 (병렬, 워크플로우)
페이지 수가 많으면 **Workflow로 fan-out**(사용자가 멀티에이전트에 옵트인한 경우). 각 페이지를 `admin-page-documenter` 에이전트(또는 워크플로우 agent)로:
- 입력: 메뉴 라벨 / route / 폴더 슬러그 / 코드베이스 경로 / order
- 출력 스키마: `{folder, markdown, difficulty, captureNeeds:[{route,desc}]}`
- 워크리스트는 스크립트에 **인라인 임베드**(에이전트가 파일을 읽어 파싱하면 prose가 섞여 실패할 수 있음).
- 결과 .md를 `<guide-repo>/src/content/<folder>/<slug>.md` 에 기록.
- 각 가이드 프론트매터 다음 줄에 **어드민 원본 링크** 삽입: `> 🔗 **어드민에서 열기:** [<URL><route>](...)`.

자세한 워크플로우 스크립트 뼈대는 `reference/workflow-skeleton.md` 참고.

## 3) 캡쳐 파일명 배정 + 자리표시자 치환
- 폴더별 고유 prefix(예: `g00`, `g01`...)로 **충돌 없는** 파일명 부여: `capture-<fid>-NN.png`.
- 각 .md의 `![..](__PENDING__)` 자리표시자를 순서대로 실제 파일명으로 치환.
- 매핑을 `.worklist/capfinal.json` (`{file,folder,route,alt,desc}`) 에 저장.

## 4) 라이브 캡쳐 + 하이라이트 (직렬, Chrome MCP)
브라우저 1개라 순차 처리. 페이지마다:
1. `navigate_page(URL+route)` → 로드 대기
2. `evaluate_script` 로 자동 하이라이터 주입 (`reference/highlighter.js` 내용 사용) — 상단버튼/탭/검색필터/표헤더를 색 구분 번호 배지로 표시. 아무것도 못 잡으면 `nav`/필터 행 fallback.
3. `take_screenshot(fullPage)` → `<guide-repo>/public/captures/<file>` (반드시 워크스페이스 루트 안). fullPage 실패 시 viewport로 재시도.
4. 가끔 `Read` 로 결과 검증, 어긋나면 재주입.
5. 권한 없음(401)·서버 에러(500)·다이얼로그는 `handle_dialog`로 닫고 `.worklist/capture_skips.log`에 사유 기록 후 다음으로.
- **우선순위**: ① 모든 페이지의 대표 화면 1장(가장 가치 큼) → ② 고난도 페이지 정밀 다중 캡쳐 → ③ 하위/상세(`[id]`)·웹 비교 캡쳐.
- 진행상황을 `.worklist/capture_remaining.json` 에 계속 갱신해 **언제든 재개 가능**하게.

> 💡 **웹/앱 비교 캡쳐**: 설정이 클라이언트에 보이는 결과가 있으면(프로모션·홈피드·배너·탭 등) 라이브 웹/앱의 해당 화면도 나란히 캡쳐하면 "설정=결과" 비교가 된다.

## 5) 미완 캡쳐 처리 + 검증
- 아직 못 찍은 캡쳐 참조는 깨진 이미지 대신 **`> 📷 _(캡쳐 준비 중)_ <설명>`** 플레이스홀더로 치환(렌더 깔끔하게).
- 빌드/렌더 검증(가이드 사이트의 build 명령). 사이드바·링크·이미지·플레이스홀더 정상 확인.
- 임시 파일 정리. `.worklist/`는 `.gitignore`에 추가.
- **커밋은 사용자가 요청할 때만.**

## 실제 적용 사례(Next.js Pages Router 어드민)에서 검증된 것
92개 페이지 → 개별 폴더 가이드(약 16k줄) + 87개 대표 화면 캡쳐. 자동 하이라이터가 일반 MUI/테이블 어드민에서 잘 동작. react-select·커스텀 nav 페이지는 fallback 필요. fullPage 스크린샷이 매우 긴 페이지에서 실패 → viewport 재시도로 해결.
